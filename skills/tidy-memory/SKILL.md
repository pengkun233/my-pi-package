# 整理项目知识

默认范围是当前项目的 project memory，以及仓库自有的 `CLAUDE.md`、`AGENTS.md` 和 `README.md`。按用户追加要求调整范围；global memory 仅在明确要求时纳入。

## 盘点

读取当前磁盘上的完整 project memory，并找出仓库自有的全部目标文档；依赖、构建产物、vendor 和生成缓存不属于范围。用代码、配置、测试、命令输出及必要的 Git 历史核实其中的实质性陈述。

把 memory 与文档视为同一个知识集合。每个 memory topic 和每条实质性文档内容都必须得到一个裁决：**保留、合并、修正、删除或待查**。

盘点完成标准：范围内的全部内容都已有裁决、事实依据和权威归属。

## 归位

- **Memory** 保存经验证、长期有效、可复用且不容易直接从仓库查到的知识。
- **`AGENTS.md` / `CLAUDE.md`** 保存代理执行当前仓库工作所需的约束、约定和流程。
- **`README.md`** 保存面向使用者的当前能力、安装、用法和公共约定。
- **代码与配置** 是名称、版本、清单和默认值的事实源；README 仍保留使用公共接口所需的命令和示例。

同一含义合并到一个权威正文，并保全各处独有信息；其他必要入口改为最小摘要或可达指针。按事实源修正冲突内容。删除已失效、被取代、仅描述临时任务、重复且无独有价值的内容。证据不足的内容保持原状并归入待查。

按依赖安全的顺序实施裁决，不预设 memory 与文档的处理先后。

Memory 的安全边界：以磁盘上的最新索引为准；`upsert` 前读取完整 topic；合并 topic 时先写入完整 canonical topic，再删除已被吸收的 topic。若目标文档由其他来源生成或管理，修改权威源并运行仓库已有的生成流程。保留用户原有工作区改动；敏感值只执行清理，不在修改记录或报告中复述。

归位完成标准：有效的独有信息全部保留；范围内不再存在语义重复、已知矛盾、错误或过期内容；每条保留内容均位于正确职责且所有指针可达。

## 验收

重新索引并核对 memory，验证修改涉及的路径、链接、命令和事实，运行仓库已有的针对性检查，并执行 `git diff --check`。

最终报告列出 memory 与文档的合并、修正和删除结果，说明验证依据，并单列缺失文件与待查项。
