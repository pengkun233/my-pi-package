# Auto Drive

主对话负责调度和决策，副对话负责实现。复用现有 `implement`，不另加实现、测试或审查流程。

## 开始

1. 读取并遵循 `herdr` skill，包括环境检查和当前 CLI 用法。仅在 Herdr 管理的 pane 内执行。
2. 从用户给出的链接列表或明确指定的 ready-for-agent 队列取得本批 tickets，按给定顺序逐条处理。队列来源不明确时先问清楚。
3. 使用用户指定的 agent；未指定时沿用当前主对话的 agent 类型，启动全新会话。副对话需要支持 `/implement`。如果该命令不可用，报告配置阻塞，不擅自换成另一条实现指令。
4. 在系统临时目录创建本次运行独有的 Markdown 报告，告知路径。主对话持续更新它，不要求副对话在启动时写报告。

## 每张 ticket

### 1. 开 pane 并派工

在主 pane 右侧创建新 pane，保持当前工作目录和用户焦点，启动全新副对话。使用 Herdr 返回的 pane ID 和 agent 标识。

第一条消息必须恰好是下面这一行，将占位符替换为当前 ticket 的链接；不添加任何说明、上下文或报告要求：

```text
/implement <ticket 链接>
```

### 2. 等待与决策

使用 Herdr 的 agent 等待和读取能力跟进。执行 ticket 通常耗时较长，初次等待可设长一些，例如 30 分钟；后续根据进展调整等待时长，减少无效检查。等待超时但仍在工作时继续等待，不重新派发 ticket。`idle`、`done` 或 `blocked` 只是交互状态：读取输出，区分完成汇报和提问；`unknown` 不代表完成。

副对话提问或无法继续时，主对话读取原因，依据 ticket、项目惯例和已有授权作出合理决定，发消息让它继续，并立即将问题、决定和理由记入报告。普通实现选择不转问用户；选择最小、可逆且满足需求的方案。

涉及缺失权限、不可用服务或超出已有授权的操作时，不能靠虚构授权或绕过安全限制继续。保存成果并记录阻塞，不把未完成的 ticket 关掉。没有新证据时不重复同一失败操作。

### 3. 补齐收尾

读取副对话的最终汇报，确认实现结果以及 commit、push、关票状态。状态不清楚就让它确认，不能把“已实现”当成“已 push 并关票”。

- 已完成、已 push、已关票：记录结果。
- 缺少收尾：只发送必要的跟进消息，让它补齐 commit（如需）、push 和关票；等它确认完成，再推进下一张。
- 不能关票或不能收尾：先按上面的决策规则处理。仍无法解决则记录阻塞和保存成果的位置，跳过当前 ticket。

调用此 skill 授权提交并正常 push 本批实现、关闭已完成的 tickets；不包含强制 push、合并、部署或其他破坏性操作。

### 4. 记录并关闭

在关闭前更新报告：ticket 链接、最终结果、可获得的提交/分支信息，以及代做的决定和未解决事项。确保副对话已停止工作，成果已保存，再关闭本次创建的 pane。

关闭 pane 不会清除工作区修改。若跳过的 ticket 留有未隔离改动，让副对话先安全保存并隔离；无法安全隔离则停止本批，保留现场，不丢弃改动或让下一张接着处理这些改动。

关闭后才为下一张 ticket 创建新 pane。只关闭本次创建的 pane。

## 结束

队列耗尽后，向用户提供报告路径和简短汇总：完成、阻塞、未执行的 tickets，以及需要关注的决定。若当前会话无法继续或遇到影响整批的环境阻塞，记录停止原因和剩余 tickets 后结束，不宣称会话退出后仍会自动运行。

报告保持简短，每张 ticket 一节即可：

```markdown
## <ticket 链接>
- 结果：完成 / 阻塞；commit、push、关票状态；成果位置
- 问题与决定：遇到的问题 → 主对话的选择及理由（没有则省略）
- 未解决事项：需要什么才能继续（没有则省略）
```
